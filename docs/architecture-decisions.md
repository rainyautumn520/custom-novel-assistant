## ADR-01 进程拓扑：Electron 如何与 FastAPI 共存

**背景**：桌面端同时有 Electron（React 渲染进程）和 FastAPI 本地服务。需要确定两者的启动、端口与生命周期管理方式。

**裁决**：生产环境由 Electron 主进程负责 spawn FastAPI 子进程，端口**动态分配**，不再固定使用 8000。

- 开发模式：前后端各自独立启动（`npm run dev` + `uvicorn`），与现状一致，便于热更新。
- 生产模式：主进程启动时探测空闲端口（监听 `127.0.0.1:0` 获取操作系统分配端口），把端口和令牌通过环境变量传给后端子进程；后端就绪后通过 stdout 上报 `READY {port}`，主进程确认后再创建渲染窗口。
- 退出顺序：先关闭渲染窗口，再向子进程发送 SIGTERM/终止信号，等待优雅退出；超时 5 秒强制结束。
- 安全：后端只监听 `127.0.0.1`；启动时生成一次性本地令牌，渲染进程通过 preload 暴露的 API 携带令牌访问，防止本机其他进程直接调用。

**理由**：固定端口在用户机器上易冲突（8000 常被占用）；本地服务不应暴露到局域网。

**影响**：dev-setup.md 中固定 `--port 8000` 仅适用于开发；生产打包需维护子进程 spawn 与健康检查逻辑。

## ADR-02 数据隔离：单库多作品 vs 每作品独立库

**背景**：PRD 待决策项，影响备份、损坏恢复与未来 `.story-system` 演进。

**裁决**：**每部作品独立 SQLite 数据库 + 一个应用级元数据库**。

```text
~/ai-novel-ide-data/
├── app.db                  # 应用级元库：最近作品、全局设置、凭证引用
└── workspaces/
    └── <project_id>/
        ├── novel.db        # 该作品全部结构化数据
        ├── chapters/       # 正文 Markdown 文件
        ├── snapshots/      # 章节快照
        ├── assets/         # 素材文件
        └── vectors/        # ChromaDB 向量库（v0.2）
```

**理由**：

- 单作品损坏不影响其他作品；备份/恢复/迁移以作品目录为单位，语义清晰。
- 作品目录天然成为未来 `.story-system` 真源目录的载体（可随版本演进加入 `volumes/`、`chapters/` 合同链）。
- 跨作品能力（最近作品、全局搜索入口）由 app.db 承担，MVP 全局搜索按作品展开。

**影响**：所有业务查询必须携带 `project_id`；Alembic 迁移针对作品库执行；删除作品 = 删除整个 workspaces 目录（进回收站）。

## ADR-03 正文存储：数据库 vs 独立文件

**背景**：PRD 待决策项，涉及原子保存、版本策略与导出可靠性。

**裁决**：**正文以独立 Markdown 文件存储，数据库只存元数据与快照指针**。

| 内容 | 存储位置 |
|---|---|
| 正文内容 | `workspaces/<project_id>/chapters/<chapter_id>.md` |
| 章节元数据（标题、字数、大纲关联、更新时间、文件哈希） | `novel.db` 的 `chapters` 表 |
| 版本历史 | `snapshots/<chapter_id>/<timestamp>_<hash>.md` + `snapshots` 表 |

原子保存流程：

1. 渲染进程防抖 800–1500 ms 后发送保存请求。
2. 后端把最新正文写入 `chapters/.tmp/<chapter_id>.md.tmp`。
3. `fsync` 后原子 `rename` 覆盖正式文件。
4. 覆盖前把上一版本复制到 snapshots（保留最近 N 份，默认 20，可配置）。
5. 更新 `chapters` 表元数据与 `snapshots` 表指针；任一步失败整体回滚，正文文件保持旧版本。

**理由**：

- Markdown 文件作者可直接打开、备份、纳入 Git，符合"本地优先、作者掌控"。
- 正文不进数据库可避免大文本对 SQLite 的读写压力，且全文检索/向量化可基于文件做增量索引。
- 快照文件化让"章节级快照"成本可控，避免全文 Git 版本库过大。

**影响**：导出、搜索、向量化均以文件系统为正文真源；数据库只读文件哈希校验一致性，不一致时标记"文件缺失/被外部修改"。

## ADR-04 密钥存储：跨平台统一抽象

**背景**：PRD 要求 API Key 不进入 Git、导出与日志；v0.2 需要保存 Seedream/DeepSeek 凭证。

**裁决**：采用 **Electron `safeStorage` 统一抽象**（Windows DPAPI / macOS Keychain / Linux libsecret），开发模式允许 `.env` 兜底。

```text
SecretStore 接口（preload 暴露给渲染进程）
├── set(key, value)      # 加密后写入 app.db 的 secrets 表
├── get(key)             # 解密读取，仅在后端调用时注入
└── delete(key)
```

规则：

- 渲染进程只能读写"凭证是否存在/已配置"的布尔状态，不能读取明文。
- 后端发起 AI/封面请求时，通过主进程 IPC 临时注入密钥，不落盘、不进日志。
- `.env` 仅用于开发环境，且必须被 `.gitignore` 排除。

**理由**：safeStorage 是 Electron 官方跨平台方案，比自研加密可靠；应用级元数据库只保存密文引用。

**影响**：Linux 无钥匙环时需提供降级提示（safeStorage 不可用则禁止保存凭证，仅允许运行时临时输入）。

## ADR-05 Seedream 5.0 调用：配置化与幂等重试

**背景**：PRD 要求封面生成，但正式模型标识、鉴权、尺寸与费用策略未确认。

**裁决**：封面服务采用**配置驱动**接入，模型标识、端点、尺寸与费率参数集中在配置中，不硬编码。

- 配置默认值以火山方舟/豆包官方文档为准；模型标识写成 `doubao-seedream-5.0`（占位），**正式上线前必须联调确认**并在本文更新。
- 生成任务表记录：提示词、参数、请求时间、状态（queued/running/success/failed/cancelled）、结果文件引用、幂等键。
- 重试幂等：每次调用生成唯一 `idempotency_key`，失败重试复用同一键，防止重复扣费/重复任务。
- 尺寸限制：按官方支持列表在 UI 中枚举，不开放自由输入；费用估算在提交前展示。

**理由**：外部 API 参数可能随版本变化，配置化可避免每次升级改代码；幂等键是"失败重试不重复扣费"的验收硬要求。

**影响**：新增 `cover_providers` 配置段；联调完成后只需改配置与测试，不改架构。

## ADR-06 AI 请求取消与幂等

**裁决**：AI 流式请求使用 **SSE**，前端通过 `AbortController` 取消；后端收到取消即停止生成并释放任务；落库写入使用幂等键（会话 ID + 请求序号）防止重复提交。

**理由**：续写/讨论可能耗时长，用户必须能随时取消；断网/超时重试不能造成重复入库。

## ADR-07 数据库迁移策略

**裁决**：SQLAlchemy 2.0 + Alembic。应用级库与作品库各维护一套迁移链：

```text
alembic/app/     # app.db 迁移
alembic/novel/   # 每个作品 novel.db 迁移（新建作品时执行 upgrade head）
```

每个作品库记录 `schema_version`；打开作品时版本不匹配则阻止写入并要求迁移/恢复。

**理由**：单库多作品时代一份迁移即可，作品库方案要求迁移可对任意新库重复执行。

## ADR-08 导出编码与一致性

**裁决**：TXT 导出统一 **UTF-8（Windows 下带 BOM）**，章节顺序以大纲树为准，导出前生成章节清单供确认；失败时报告未导出项并保证已导出文件不半写（临时文件 + rename）。

**理由**：中文 + Emoji + Markdown 符号必须无乱码；Windows 记事本对无 BOM UTF-8 识别差，带 BOM 兼容性最好。

---

## ADR-09 日志脱敏

**裁决**：日志禁止包含正文、设定、提示词、文件路径与密钥。采用结构化日志：

```text
{ts, level, request_id, module, event, duration_ms, outcome}
```

正文内容最多记录长度与哈希，便于排查不泄露内容；本地诊断页可导出脱敏日志。

---

## ADR-10 未来 `.story-system` 演进预留

**裁决**：作品目录即未来真源目录。MVP 阶段 `novel.db` 是结构化真源；v0.4 演进时在作品目录内增加 `.story-system/`（设定合同、卷/章合同、提交链）并让 `novel.db` 中的状态表与之同步，不推翻本文数据结构。

**理由**：参考 webnovel-writer 的"真源与投影分离"，保证数百章场景下设定可追溯、可重建。

## 决策影响一览

| 决策 | 影响模块 | 风险与缓解 |
|---|---|---|
| ADR-01 动态端口 + 本地令牌 | Electron 主进程、IPC、后端启动 | 端口探测竞态 → 主进程等待 READY 确认 |
| ADR-02 每作品独立库 | 存储层、迁移、备份 | 跨作品统计需 app.db → MVP 不提供跨作品聚合 |
| ADR-03 正文文件化 | 编辑器、保存、导出、搜索 | 外部修改文件 → 哈希校验 + 状态提示 |
| ADR-04 safeStorage | 设置、AI/封面调用 | Linux 无钥匙环 → 降级提示 |
| ADR-05 Seedream 配置化 | 封面工坊 | 模型标识未最终确认 → 上线前联调 |
| ADR-06 SSE + 幂等 | AI 讨论、续写 | 取消语义复杂 → 后端任务状态机 |
| ADR-07 双迁移链 | 数据库层 | 版本不匹配 → 打开作品时闸门 |
| ADR-08 UTF-8 BOM 导出 | 导出中心 | 跨平台工具链差异 → 导出测试用例覆盖 |
| ADR-09 日志脱敏 | 全部模块 | 遗漏字段 → 诊断页审查 + 测试 |
| ADR-10 真源目录演进 | 存储层 | 双重真源风险 → v0.4 前保持 novel.db 唯一真源 |
