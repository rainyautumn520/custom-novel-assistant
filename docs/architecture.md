## 2. 子系统职责卡

### 2.1 世界观系统

- **职责**：管理小说的世界观设定（规则、地理、历史、势力、种族等）
- **数据**：World → SettingCategory → SettingItem（树形结构）
- **关联**：一对多关联人物、大纲节点、章节
- **MVP 范围**：CRUD + Markdown 描述 + 分类标签

### 2.2 人物系统

- **职责**：角色卡管理、人物关系图谱、成长弧线追踪
- **数据**：Character（姓名/性别/年龄/身份/性格/外貌/背景故事）
- **关联**：多对多人物关系，关联世界观、大纲节点
- **MVP 范围**：CRUD + 关系定义 + 列表/卡片视图

### 2.3 大纲系统

- **职责**：层级化大纲编排（卷→章→节）、情节时间线
- **数据**：OutlineNode（树形递归结构，parent_id 自引用）
- **关联**：节点关联人物、世界观设定、章节正文
- **MVP 范围**：三层树形 + 拖拽排序 + 节点摘要

### 2.4 正文编辑器

- **职责**：分章写作、Markdown 实时预览、版本快照
- **数据**：Chapter（正文 Markdown、字数、版本历史）
- **关联**：关联大纲节点、出场人物、引用的设定
- **MVP 范围**：CodeMirror 编辑器 + Markdown 预览 + 自动保存

### 2.5 素材库

- **职责**：参考资料、灵感片段、图片集中管理
- **数据**：Asset（文件路径/文本内容、类型、标签）
- **关联**：可关联到任何实体（世界观/人物/章节）
- **MVP 范围**：文件夹管理 + 图片/文本上传 + 标签检索

### 2.6 AI Agent 系统（v0.2+）

- **职责**：多角色 Agent 协作，覆盖创作流程不同阶段
- **Agent 角色**：
  - 编剧 Agent：情节冲突建议、伏笔管理
  - 作者 Agent：续写建议、文风模仿
  - 编辑 Agent：语法纠错、敏感词检测、一致性检查
  - 数据分析 Agent：写作习惯分析、读者反馈（远期）
- **MVP 范围**：不纳入 MVP，v0.2 从编辑 Agent 开始

### 2.7 RAG 知识库（v0.2+）

- **职责**：将全部设定和正文向量化，提供 AI 上下文检索
- **流程**：文档 → 切片 → BGE-M3 嵌入 → ChromaDB → 相似度检索
- **触发**：编辑器 @ 触发、Agent 自动检索
- **MVP 范围**：不纳入 MVP，v0.2 上线基础版

### 2.8 知识图谱（v0.2+）

- **职责**：可视化实体关系（人物-世界观-章节-素材）
- **技术**：前端 Canvas/SVG 力导向图（D3.js/Cytoscape.js）
- **交互**：节点点击跳转详情、拖拽重排、关系筛选
- **MVP 范围**：不纳入 MVP，v0.2 上线基础版

### 2.9 节奏分析（v0.3+）

- **职责**：章节字数趋势、情节密度热力图、高潮间隔标注
- **数据**：章节字数统计 + 情节事件标注
- **MVP 范围**：不纳入 MVP

### 2.10 数据分析（v0.3+）

- **职责**：日写作字数、活跃时段、完本进度预估
- **数据**：写作会话日志聚合
- **MVP 范围**：不纳入 MVP

## 3. 关键数据流

### 写作流程数据流

```
世界观设定 → 人物创建 → 大纲编排 → 章节撰写
     │            │           │           │
     └────────────┴───────────┴───────────┘
                      │
               RAG 知识库索引 (v0.2)
                      │
               AI Agent 上下文 (v0.2)
```

### AI 辅助流程（v0.2）

```
用户选中文本 → 编辑器发送上下文 → API Gateway
                                    │
                    ┌───────────────┼───────────────┐
                    │               │               │
               RAG 检索        Agent 路由       知识图谱
               (ChromaDB)     (LangChain)     (关系查询)
                    │               │               │
                    └───────────────┼───────────────┘
                                    │
                            LLM 调用 + Prompt
                                    │
                            SSE 流式返回前端
```

### 本地存储与备份

```
SQLite 主库 (结构化数据)
    ├── worlds, characters, outlines, chapters, assets
    └── 每个写操作自动保存

ChromaDB (向量嵌入, v0.2)
    └── 设定/章节的嵌入向量

文件系统
    └── 素材图片 / Markdown 导出备份
```

## 4. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 本地数据库 vs 云端 | 本地 SQLite MVP | 单用户，离线可用，零运维 |
| REST vs GraphQL | REST | FastAPI 原生支持，前端 React Query 成熟 |
| 实时同步 vs 手动保存 | 自动保存 + 去抖 | 写作场景怕丢稿，自动保存 2 秒去抖 |
| 版本管理策略 | 章节级快照 | 全文 Git 太重，章节级 diff 即可 |
| Agent 同步 vs 异步 | 异步 (Celery) | 续写/分析可能耗时长，避免阻塞 UI |
| 插件系统 | 预留接口，v1.0 上线 | MVP 硬编码核心功能，架构预留 hook |
| 前端路由 | React Router (内存路由) | Electron 无 URL，用 HashRouter |

## 5. 安全与隐私

| 层面 | 措施 |
|------|------|
| 数据传输 | 本地应用无网络传输（MVP）；AI API 调用 HTTPS |
| 数据存储 | SQLite 本地文件，用户完全掌控 |
| API Key | 本地环境变量，不上传 |
| AI 数据隐私 | 仅发送必要上下文，不发送全量稿件 |
| 备份 | 手动 Markdown 导出，SQLite 文件可复制 |
