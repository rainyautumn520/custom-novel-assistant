# 功能与页面结构审核

> 阶段：1 | 状态：通过（带后续技术决策项） | 日期：2026-07-14

## 1. 审核结论

当前产品结构可收敛为九个 MVP 页面与四个 v0.2 页面。核心闭环完整，模块边界清晰；但原文档把“素材库”放入 MVP、把全部 AI 放到 v0.2，同时新增需求又要求设定讨论与封面生成。最终裁决是：**MVP 保持离线创作闭环，AI 讨论和封面作为 v0.2；现在完成页面与接口契约设计，不阻塞 MVP。**

阶段一结论：

- 功能范围：通过。P0/P1、版本边界和验收标准已定义。
- 页面结构：通过。入口唯一、模块不重复、跨页主流程可闭环。
- 长篇一致性：通过。PRD 已引入章纲合同、人工确认和事实优先级。
- 数据安全：通过。已要求自动保存三态、原子写入、覆盖确认和凭证隔离。
- 技术实现：留待阶段二/三，不在阶段一提前锁死具体表结构和进程方案。

## 2. 功能去重与边界裁决

| 争议项 | 裁决 | 理由 |
|---|---|---|
| “作品”与“世界观”关系 | 作品是顶层容器，设定是作品内模块 | 避免把一个“世界”误当一部作品，支持一部作品多个位面/时代 |
| 人物是否属于设定 | UI 独立模块，底层允许统一实体关联 | 角色编辑字段与筛选密度高，独立入口更高效 |
| 章节与章纲是否同一对象 | 分离但一对一可关联 | 章纲是计划，章节是正文；必须允许有纲无文、先文后补纲 |
| AI 聊天是否放编辑器右栏 | 轻量操作在右栏，完整会话有独立页 | 避免长会话挤压正文，又保留就地协作效率 |
| 导出入口 | 独立导出中心 + 章节快捷导出 | 单章高频、整书高风险，两种场景都覆盖 |
| 封面是否属于素材库 | 独立“封面工坊”，输出可进入素材 | 封面含生成任务、排版和导出，不是普通素材 CRUD |
| 自定义 skill 放哪里 | 全局设置管理，编辑器选择启用 | 管理与使用分离，避免正文界面承担复杂配置 |

## 3. 导航模型

采用“项目首页 → 作品工作台”两级应用模型。进入作品后，左侧导航固定为：概览、设定、人物、大纲、正文、素材、导出；v0.2 增加 AI 讨论和封面。

关键约束：

- 全局设置不属于某一作品；作品级 AI 提示词和 skill 属于作品。
- 当前作品、当前章节和保存状态在切换模块时保持。
- 任何详情对象都应提供稳定深链接，方便搜索结果和关联项跳转。
- 面包屑仅用于层级深处（如“设定 / 势力 / 北境联盟”），不与左侧主导航重复。

## 4. 关键页面审核

### P01 项目首页

**主任务**：快速继续最近作品或新建作品。  
**首屏优先级**：继续写作 > 最近作品 > 新建作品 > 归档。  
**必须状态**：首次使用空状态、路径丢失、项目损坏、已归档。  
**审核意见**：不展示复杂数据面板，减少首次使用门槛。

### P04 设定库

**布局**：分类树 / 条目列表 / Markdown 编辑区 / 关联与标签侧栏。  
**必须交互**：快速新建、搜索、高亮未保存、引用影响提示。  
**v0.2 扩展**：“讨论此设定”和“从讨论纳入”入口。  
**审核意见**：分类与标签分工明确——分类单选用于归档，标签多选用于横向检索。

### P06 大纲编排

**布局**：左侧三级树，中间节点编辑，右侧人物/设定引用。  
**必须交互**：拖拽、键盘移动、复制节点、折叠卷、从章纲创建正文。  
**风险控制**：非法父级拒绝、删除前显示子节点数、保存失败回滚。  
**审核意见**：暂不采用无限层级，确保卷/章/细纲语义稳定。

### P07 正文编辑器

**布局**：章节树 / 编辑区 / 可选预览 / 上下文侧栏。  
**持续可见**：章节名、字数、保存状态、当前章纲。  
**必须状态**：保存中、已保存、失败待重试、离线 AI 不可用。  
**审核意见**：保存状态不得只用图标；预览和 AI 面板均可收起，为写作留出空间。

### P09 导出中心

**布局**：导出类型、范围与排序、格式选项、路径、结果。  
**风险控制**：导出前预览章节清单；覆盖确认；失败给出未导出项。  
**审核意见**：导出不是设置项，应作为作品级主功能可直接访问。

### P12 AI 设定讨论（v0.2）

**布局**：会话列表 / 对话 / 当前引用上下文 / “纳入设定”操作。  
**风险控制**：AI 回答与正式设定视觉区分；保存前可编辑；冲突显式提示。  
**审核意见**：AI 只能提出候选事实，不可静默写入设定。

### P13 封面工坊（v0.2）

**步骤**：需求 → 优化提示词 → 候选生成 → 文字排版 → 导出。  
**必须状态**：排队、生成中、成功、失败、取消、凭证未配置。  
**风险控制**：费用/次数提示、失败重试幂等、原图与排版图分离。  
**审核意见**：采用分步流程，避免把提示词、生成历史和排版工具堆在一屏。

## 5. 跨页面主流程验收

| 流程 | 起点 | 终点 | 通过条件 |
|---|---|---|---|
| 首次建书 | 项目首页 | 第一章正文 | 10 分钟内完成，无死路 |
| 规划到写作 | 大纲章节点 | 对应章节 | 一键创建/打开，章纲上下文可见 |
| 引用设定 | 正文/大纲 | 设定详情 | 可跳转并返回原位置 |
| 删除设定 | 设定详情 | 删除结果 | 删除前显示引用影响，可取消 |
| 整书导出 | 导出中心 | TXT 文件 | 清单、顺序、编码正确 |
| 讨论入库 | AI 讨论 | 正式设定 | 必经预览与确认，记录来源 |
| 封面输出 | 封面工坊 | 本地图片 | 原图不变，排版与预览一致 |

## 6. 全局交互一致性

- 创建使用主按钮；编辑自动保存；显式“保存”只用于高风险配置或 AI 结果纳入。
- 删除统一使用危险样式和二次确认；能恢复的优先归档/回收站。
- Toast 只报告短暂结果；需要用户处理的失败必须保留在页面内。
- 搜索结果统一显示类型、标题、命中摘要和所在作品。
- 空状态必须解释当前页面用途并给出唯一主操作。
- 所有拖拽操作提供键盘替代与撤销入口。

## 7. 未通过方案与原因

以下方案已审视并否决：

1. **把所有模块放在单页看板**：信息密度过高，长时间写作空间不足。
2. **用任意层级大纲替代固定三级**：灵活但语义不稳定，增加导出、章纲映射和 AI 上下文复杂度。
3. **AI 自动把聊天结论写入设定**：不可审计，容易将幻觉升级为正式事实。
4. **把 API Key 存在作品配置**：备份/分享项目时可能泄露。
5. **只显示“已保存”图标**：失败时不明显，不能满足正文安全要求。
