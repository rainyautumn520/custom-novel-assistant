# MVP 范围定义

> AI Novel IDE — 面向网文作者的 AI 创作操作系统
> 版本：v0.1-draft | 日期：2025-07-13

> **状态说明（2026-07-14）**：本文保留为阶段 0 范围草案。阶段 1 已完成评审，后续产品与验收以 [产品需求文档](prd.md) 和 [功能与页面结构审核](information-architecture.md) 为准。

## 1. 产品愿景

打造覆盖网文创作全流程的 AI 协作平台：从世界观建立、人物塑造，到大纲编排、正文撰写，再到 AI 辅助修改与数据分析——在一个工具内完成从灵感到成品的完整闭环。

核心设计理念：
- **Obsidian 知识图谱**：可视化实体关系（人物、地点、事件），自由链接
- **Notion 资料管理**：结构化存储世界观、角色卡、素材，灵活检索
- **Cursor AI 协作**：上下文感知的智能补全、改写、审稿

---

## 2. 核心子系统总览

| # | 子系统 | 简介 |
|---|--------|------|
| 1 | 世界观系统 | 管理规则、地理、历史、势力等设定 |
| 2 | 人物系统 | 角色卡、人物关系、成长弧线 |
| 3 | 大纲系统 | 层级化大纲（卷→章→节），情节编排 |
| 4 | 正文编辑器 | 分章写作，Markdown 预览，版本管理 |
| 5 | 素材库 | 参考资料、灵感片段、图片集中管理 |
| 6 | AI Agent | 编剧/作者/编辑/分析等多角色系统 |
| 7 | RAG 知识库 | 基于全部设定和正文的 AI 上下文检索 |
| 8 | 知识图谱 | Obsidian 风格可视化实体关系图 |
| 9 | 节奏分析 | 字数、情节密度、高潮间隔统计 |
| 10 | 数据分析 | 写作习惯、产出效率、数据面板 |

## 3. MoSCoW 优先级矩阵

### Must Have — MVP v0.1

| 子系统 | 范围 | 验收标准 |
|--------|------|----------|
| 世界观系统 | CRUD + 分类标签 + Markdown | >=3 个世界观，每个 >=5 条目 |
| 人物系统 | 角色卡 + 关联世界观 | >=10 个角色 |
| 大纲系统 | 三层大纲 + 拖拽排序 + 摘要 | 3 卷 30 章大纲树 |
| 正文编辑器 | Markdown 预览 + 自动保存 + 字数 | >=5000 字流畅编辑 |
| 素材库 | 文件夹 + 上传 + 标签检索 | >=50 条素材 |

> **MVP 最小闭环：世界观 → 人物 → 大纲 → 正文**

### Should Have — v0.2

| 子系统 | 范围 |
|--------|------|
| AI Agent（基础） | 编辑 Agent + 续写建议 |
| RAG 知识库 | 设定向量化，编辑器 @ 触发检索 |
| 知识图谱（基础） | 力导向图，点击跳转 |

### Could Have — v0.3

| 子系统 | 范围 |
|--------|------|
| 节奏分析 | 字数趋势图、密度热力图 |
| 数据分析 | 日写作量、活跃时段、完本进度 |
| Agent 扩展 | 编剧 Agent、数据分析 Agent |

### Won't Have — v1.0 前

| 项目 | 原因 |
|------|------|
| 多用户/云端同步 | MVP 本地单用户 |
| 移动端 | 先聚焦桌面端 |
| 第三方发布对接 | 核心流稳定后再做 |
| AI 生成完整章节 | AI 辅助，非 AI 代写 |

---

## 5. MVP 不做的权衡

| 不做 | 替代方案 |
|------|----------|
| 自动云备份 | SQLite + 手动导出 Markdown |
| 实时协同 | 单用户本地文件 |
| AI 训练/微调 | 现成 API（DeepSeek、GPT） |
| 插件市场 | 核心硬编码，架构预留扩展点 |
| 权限系统 | 单用户即所有者 |

---

## 6. 风险与假设

| 风险 | 缓解措施 |
|------|----------|
| Electron 体积大 | MVP 可先用 localhost Web 版 |
| AI API 成本高 | Ollama 本地模型降级 |
| 作者黏性低 | 阶段 0 沟通用户，阶段 5 可用性测试 |
| 图谱性能下降 | 轻量 Canvas/SVG，避免重型图数据库 |
