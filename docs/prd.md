# AI Novel IDE 产品需求文档（PRD）

> 文档状态：阶段一已审核基线  
> 版本：v0.2 | 日期：2026-07-14  
> 适用范围：桌面端、本地单用户、中文网文长篇创作

## 1. 产品定义

AI Novel IDE 是面向长篇连载作者的创作工作台。它以“项目”为边界，把设定、大纲、章节、素材和 AI 协作放进同一条可追踪的创作链路，目标不是一次生成一篇文本，而是在数百章规模下持续保持设定、人物、时间线和伏笔的一致性。

### 1.1 核心价值

1. **一处管理**：设定、人物、大纲、正文和素材不再散落在多个工具。
2. **长篇一致**：写作前加载明确约束，写作后沉淀确认事实，减少“写着写着忘了”。
3. **作者掌控**：AI 提供讨论、建议、起草和审查；纳入设定、覆盖正文、提交事实均由作者确认。
4. **本地优先**：项目数据默认保存在本机，可导出、可备份，核心写作不依赖在线服务。

### 1.2 目标用户

主要用户是独立中文网文作者，典型特征是同时维护 1–5 部作品、单部预计 30 万字以上、对人物与伏笔一致性敏感，并愿意用 AI 提升规划和修订效率，但不愿失去创作控制权。

### 1.3 北极星指标

**每周完成并成功保存的有效章节数。**“有效章节”指正文不少于 500 字，且保存后可重新打开、内容无损。

辅助指标：首次建书完成率、首次完成“设定→大纲→正文”的比例、自动保存成功率、章节导出成功率、AI 建议采纳率、7 日回访率。

## 2. 产品原则与事实优先级

### 2.1 产品原则

- 大纲即法律：AI 写作必须加载当前章纲，不得静默偏离。
- 设定即物理：已确认设定是生成与审查的硬约束。
- 发明需识别：AI 新增的角色、地点、物品和规则必须显式标记，未经确认不得进入正式设定。
- 真源与投影分离：正式项目数据是唯一写入口；搜索索引、摘要和向量是可重建投影。
- 少打扰：仅在创作方向冲突、一致性冲突、覆盖或删除风险时阻塞询问。

### 2.2 冲突裁决顺序

用户本次明确指令 > 当前章纲与章节目标 > 已确认设定 > 已提交章节事实 > AI 推断与历史对话。

## 3. 版本范围与产品闭环

### 3.1 MVP（v0.1）

MVP 必须跑通：**新建作品 → 建立设定 → 创建三级大纲 → 编写章节 → 自动保存 → 导出**。

| 模块 | MVP 范围 | 明确不含 |
|---|---|---|
| 项目 | 新建、打开、重命名、归档、最近打开 | 云同步、多人协作 |
| 设定 | 分类、条目 CRUD、Markdown、标签、搜索 | 知识图谱、向量检索 |
| 人物 | 角色卡 CRUD、标签、关联设定 | 自动关系推断 |
| 大纲 | 卷纲→章纲→细纲；增删改；同级排序；改变层级；目标、必须节点、禁区 | AI 自动拆纲 |
| 正文 | 章节列表、Markdown/纯文本写作、字数、自动保存、保存状态、快捷键 | 多人实时编辑、发布平台对接 |
| 导出 | 单章 TXT、全书 TXT；按大纲顺序拼接 | EPUB、DOCX、平台直发 |
| 素材 | 文本素材 CRUD、标签、搜索 | 大文件管理、OCR |

MVP 数据容量验收：单部作品至少承载 3 卷、30 章大纲、10 个角色、15 条设定、50 条素材；单章 10,000 中文字符编辑无明显卡顿。

### 3.2 v0.2（AI 协作）

| 模块 | 范围 | 关键约束 |
|---|---|---|
| 设定讨论 | 与 DeepSeek 多轮讨论；把选中结论保存为设定条目 | 保存前必须预览目标分类与最终文本 |
| 正式写文 | 自由写作、AI 续写/改写、自定义 skill/提示词 | AI 不得自动覆盖正文；每次应用可撤销 |
| 写章流水线 | 上下文任务书→起草→五维审查→润色→事实提取→确认提交 | 审查与事实入账保留结构化结果 |
| 封面生成 | 用户需求→提示词优化→Seedream 5.0 生图 | API 密钥不写入项目文件或日志 |
| 封面微调 | 预览图上添加书名/作者名，支持位置、字号、颜色和导出 | 原始生成图保留，不做破坏性覆盖 |

### 3.3 后续版本

- v0.3：RAG、基础知识图谱、伏笔/时间线查询、节奏 Strand Weave 面板。
- v0.4：可恢复的章节提交链、事件审计链、投影重建与项目体检。
- v1.0 前不做：多用户、云同步、移动端、第三方平台发布、模型训练。

## 4. 核心用户旅程

### 4.1 首次建书

1. 用户在项目首页点击“新建作品”。
2. 输入书名、题材、简介、预计字数；可跳过非必填项。
3. 系统创建作品并进入作品工作台，展示“设定→人物→大纲→正文”的引导。
4. 用户完成第一条设定、第一名角色、第一条章纲和第一章正文。
5. 系统持续显示保存状态，并在重新打开后恢复到上次位置。

成功标准：新用户 10 分钟内无需阅读外部文档即可创建作品并写下第一段正文。

### 4.2 规划与写作

1. 在大纲页创建卷纲、章纲和细纲。
2. 为章纲填写目标、必须覆盖节点和禁区。
3. 从章纲直接“创建/打开正文”。
4. 编辑器右侧上下文栏展示本章合同、相关人物和设定。
5. 正文自动保存；用户可随时导出单章或整本。

### 4.3 AI 设定讨论（v0.2）

1. 用户从设定页进入讨论，选择或创建会话。
2. AI 基于当前作品与用户指定资料回答，来源范围可见。
3. 用户选中认可结论，点击“纳入设定”。
4. 系统展示可编辑预览、目标分类、冲突提示。
5. 用户确认后写入设定，并记录来源会话。

### 4.4 封面生成（v0.2）

1. 用户选择尺寸与风格，填写画面、氛围、书名和作者名。
2. 系统把需求交给 DeepSeek 优化为可编辑提示词。
3. 用户确认后调用 Seedream 5.0，展示任务状态与失败重试。
4. 用户选择候选图进入排版，添加书名/作者名并导出。

## 5. 功能需求与验收标准

### FR-01 项目管理（P0）

- 新建作品至少要求书名；书名去除首尾空格后不得为空。
- 最近作品显示书名、更新时间和当前字数；损坏或丢失路径要给出可恢复提示。
- 归档与删除分离。删除必须二次确认，MVP 默认仅支持移入回收站。
- 验收：创建后重启应用仍可打开；重命名不丢失关联数据；归档作品可恢复。

### FR-02 设定与人物（P0）

- 设定条目字段：标题、分类、正文、标签、状态、创建/更新时间。
- 人物字段：姓名、别名、身份、性格、外貌、背景、目标、标签、备注。
- 支持标题/正文/标签搜索；空状态提供创建引导。
- 验收：连续创建、编辑、删除 15 条设定和 10 个角色，重启后数据一致；删除被引用条目时明确显示影响范围。

### FR-03 三级大纲（P0）

- 固定层级为卷纲→章纲→细纲，章纲不可成为根节点，细纲不可拥有子节点。
- 支持新增、复制、删除、拖拽同级排序、拖拽改变合法父级。
- 每级字段：标题、目标、必须覆盖节点、禁区；章纲附带状态与目标字数。
- 拖拽操作必须原子保存；失败时回滚 UI 并告知原因。
- 验收：建立 3 卷/30 章树，重排后刷新顺序不变；非法层级操作被阻止；删除父节点前列出子节点数量。

### FR-04 正文编辑与自动保存（P0）

- 编辑器支持纯文本与 Markdown 常用语法，不因预览影响原文。
- 显示当前章字数、全书字数、保存中/已保存/保存失败三态。
- 输入停止 800–1500 ms 后自动保存；切换章节、关闭窗口前强制冲刷未保存内容。
- 本地保存失败时保留内存草稿，禁止用旧数据覆盖新内容，提供重试和复制全文。
- 验收：10,000 字章节连续输入、撤销、切章无内容丢失；模拟保存失败可恢复；应用异常退出后最多损失最后 3 秒输入。

### FR-05 素材库（P1）

- MVP 支持文本素材、来源、标签和备注；支持列表/卡片视图与搜索。
- 验收：50 条素材下搜索结果正确，删除与恢复行为明确。

### FR-06 导出（P0）

- 单章 TXT 使用 UTF-8；全书按卷纲与章纲顺序拼接，可选包含卷名/章名。
- 导出前展示范围、顺序、预计字数与目标路径；同名文件覆盖必须确认。
- 验收：包含中文、Emoji、Markdown 符号的章节导出后无乱码；全书章节无遗漏、无重复、顺序正确。

### FR-07 设定讨论与写作 AI（P1，v0.2）

- 多轮会话按作品隔离；用户可新建、重命名、删除会话。
- 每次请求显示进行中、可取消、失败重试；应用 AI 文本前展示差异或插入位置。
- “纳入设定”必须经过人工确认，不允许仅凭聊天内容自动改变正式数据。
- 自定义 skill/提示词按作品保存，显示启用状态和注入顺序。
- 验收：断网、超时、模型错误不会导致正文或会话丢失；AI 新发明实体会被标记。

### FR-08 封面生成（P1，v0.2）

- Seedream 调用配置包含端点、模型标识、尺寸和凭证引用；凭证进入系统安全存储。
- 生成历史记录提示词、参数、时间、状态和本地文件引用。
- Pillow 排版不得修改原图；导出前预览安全区与最终分辨率。
- 验收：API 失败可重试且不重复扣发成功任务；作者名排版导出后清晰、位置与预览一致。

```text

├─ 全局设置

│  ├─ 数据与备份
│  └─ AI 服务与凭证（v0.2）
└─ 作品工作台

   ├─ 设定
   ├─ 人物
   ├─ 大纲
   ├─ 正文
   ├─ 素材
```

### 6.2 桌面布局

- 顶栏：作品切换、全局搜索、保存状态、设置。

- 中央工作区：列表/树与内容编辑的主要区域。
- 右侧上下文栏：当前对象属性、引用、章纲合同或 AI 面板，可收起。
- 底栏：字数、同步/保存状态、快捷操作提示。

## 7. 状态、错误与安全要求

### 7.1 通用页面状态

所有数据页面必须定义：加载中、空状态、正常、局部保存中、保存成功、可重试错误、无权限/路径不可用（如适用）。不得以空白页代表异常。

### 7.2 数据安全

- 删除、覆盖、批量移动、导出覆盖属于高风险操作，必须确认并说明影响。
- 每次写入采用事务或原子文件替换，避免半写入状态。
- API Key 不进入 Git、项目导出、普通日志、错误上报或聊天上下文。
- 项目应支持手动备份；恢复前验证备份完整性并保留当前数据副本。

### 7.3 可访问性与效率

- 主要功能可用键盘访问，焦点可见；按钮不得只靠颜色表达含义。
- 正文编辑器默认字号不低于 16 px，支持字体、行高、宽度和主题调整。
- 常用操作提供快捷键：保存、搜索、切换章节、预览、打开命令面板。

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 冷启动目标 < 4 秒；普通页面交互反馈 < 100 ms；全局搜索 5,000 条记录目标 < 500 ms |
| 可靠性 | 自动保存成功率 >= 99.9%；任何失败不得静默；数据库迁移可回滚或从备份恢复 |
| 离线 | 除 AI/封面服务外，MVP 全部功能离线可用 |
| 兼容 | MVP 首发 Windows 10/11；macOS/Linux 在技术上预留但不作为首发验收项 |
| 可维护 | 关键业务规则有自动化测试；公共数据结构有版本号；日志含请求关联 ID 但不含正文与密钥 |
| 可观测 | 本地诊断页展示版本、数据目录、数据库状态、最近错误和可脱敏导出日志 |

## 9. 埋点与隐私

MVP 默认不上传创作内容。若后续启用匿名产品分析，必须显式征得同意，并仅记录功能事件、耗时和错误类别，不记录正文、设定、提示词、文件路径或 API Key。

建议事件：`project_created`、`setting_created`、`outline_reordered`、`chapter_saved`、`export_completed`、`ai_suggestion_applied`、`cover_exported`。每个事件包含应用版本、匿名本地会话 ID、耗时与结果，不包含作品内容。

## 10. 发布门槛

MVP 发布前必须全部满足：

1. 核心闭环端到端通过，重启后数据一致。
2. 自动保存、异常退出恢复、导出顺序与编码测试通过。
3. 删除/覆盖等高风险操作均有影响提示和恢复路径。
4. 关键业务逻辑单元测试覆盖率不低于 60%，核心保存与导出路径不低于 80%。
5. 30 章/10,000 字单章规模下完成性能验收。
6. 无 P0/P1 缺陷；P2 缺陷有明确规避方案。

## 11. 依赖、风险与待决策

### 已确定

- 桌面端、本地单用户、本地 SQLite。
- MVP 先完成非 AI 创作闭环，AI 与封面作为 v0.2 独立能力接入。
- 大纲使用固定三级语义，避免任意树导致后续章节映射不稳定。

### 阶段二/三需确定

- Electron 与 FastAPI 的生命周期和端口管理方式。
- 项目数据采用单库多作品还是每作品独立库。
- 正文存数据库还是独立文件，及其原子保存/版本策略。
- Seedream 5.0 的正式模型标识、鉴权方式、尺寸限制与费用策略。
- 系统安全存储在 Windows/macOS/Linux 的统一抽象。

## 12. 变更控制

本 PRD 是阶段一产品基线。任何 P0 范围变更必须同时更新：范围、页面合同、验收标准、数据模型影响与版本计划。新增 AI 能力不得绕过“预览—确认—入账”原则。
